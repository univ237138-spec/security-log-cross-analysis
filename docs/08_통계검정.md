## 통계 검정 계획: 탐지 설계의 두 가지 가정 검증

- 작성일: 2026-10-05
- 상태: 실행 완료 → [01_검정결과.md](08_통계검정.md#source-2). **가설·검정 방법·유의수준·표본 정의는 실행 전에 이 문서로 고정했고 바꾸지 않았다.**
- 관련: [Domain_Knowledge/13 분석 방법론](README.md), [07_분석기획 5절](01_프로젝트_개요.md)

### 1. 목적

이 검정은 **"공격이다"를 증명하는 것이 아니다.** 탐지 설계가 기대고 있는 **정상 행동에 대한 가정 두 개**를 데이터로 확인한다.

| # | 가정 | 이 가정에 기대는 설계 |
|---|---|---|
| 가정 1 | 정상 세션은 웹 경로와 서버 경로를 함께 쓴다 | 행위 탐지 B03(평소와 다른 접속 경로), 세션 종류 비교 |
| 가정 2 | 사람마다 세션 시작 시각 분포가 다르다 → 전체 기준선이 아니라 개인 기준선이 필요하다 | 4단계 개인(person) 기준선, B01(평소와 다른 시작 시각) |

### 2. 표본 정의

- 단위: 3단계 업무 세션 (`data/07_sessions/sessions.csv`, 146개)
- **주 분석 표본:** 분석기획 문서(10/01 작성)에 기록된 시나리오 A~D 세션 4개를 뺀 142개
  - 이 4개는 기록된 계정·시각으로 찾는다 (A dev02 10-14 18:12:18, B analyst01 10-15 05:07:03, C ops02 10-15 17:41:09, D intern01 10-16 06:19:43 UTC)
  - 탐지·점수 결과(5~7단계)로 정상을 정하지 않는다 (순환 방지)
- **민감도 분석:** 146개 전체로도 같은 검정을 하고 결과를 함께 보고한다

### 3. 검정 1: 정상 세션의 경로 동시 사용

| 항목 | 내용 |
|---|---|
| 지표 | 세션 중 `session_type = server+web` 비율 |
| H0 | 비율 p ≤ 0.90 |
| H1 | 비율 p > 0.90 ("거의 항상 함께 쓴다") |
| 기준값 0.90의 근거 | "대부분"이 아니라 "거의 항상"이라고 말하려면 10번 중 9번 넘게는 함께 써야 한다는 판단. 데이터를 보기 전 기준으로 고정한다 |
| 방법 | 정확 이항검정 (한쪽), 95% Clopper-Pearson 신뢰구간 |
| 효과 크기 | 관측 비율 − 0.90 |
| 보조 확인 | 사람별 비율 (같은 사람의 세션은 서로 독립이 아닐 수 있어, 특정 한두 명에게만 해당하는지 확인) |
| 추가 민감도 | 3단계 규칙 2 수정 전 기준(ssh 종료 뒤 웹 활동을 별도 웹 전용 세션으로 셀 때)으로도 계산 |

### 4. 검정 2: 개인별 시작 시각 차이

| 항목 | 내용 |
|---|---|
| 지표 | 세션 시작 시각 (KST, 하루 중 분 단위) |
| H0 | 8명의 시작 시각 분포가 모두 같다 |
| H1 | 적어도 한 명의 분포가 다르다 |
| 방법 | Kruskal-Wallis 검정 (정규분포를 가정하지 않는 순위 기반 검정. 사람당 세션 12~29개로 작아서 선택) |
| 효과 크기 | ε² = H / (n − 1). 0.01 작음, 0.08 중간, 0.26 이상 큼 (관행적 기준) |
| 사후 검정 | 두 사람씩 Mann-Whitney U 검정 28쌍, Holm 보정 |
| 실무 의미 확인 | 사람별 시작 시각 중앙값·사분위 범위 비교 |

**"차이가 있다"와 "개인 기준선이 필요하다"는 같은 말이 아니다.** 그래서 효과 크기와 사람별 범위를 함께 보고, 차이가 실무적으로 의미 있는 크기인지 판단한다.

### 5. 유의수준과 다중 검정

- 주 검정 2개(검정 1, 검정 2), 각각 α = 0.05. 두 검정에 Holm 보정을 적용해 함께 보고한다.
- 사후 검정(28쌍)은 별도로 Holm 보정한다.
- p값과 함께 **건수, 분모, 효과 크기, 신뢰구간**을 보고한다.

### 6. 해석 원칙

- 결과는 **탐색적**이다. 분석자가 데이터를 본 뒤 세운 가정이기 때문이다.
- 합성 데이터일 가능성이 높아, 정상 행동이 실제보다 규칙적이다. 결과를 실제 운영 환경으로 일반화하지 않는다.
- 가정이 지지되면 "탐지 설계의 근거가 이 데이터에서 뒷받침된다"로만 표현한다.
- 가정이 지지되지 않으면 그대로 보고하고, 해당 탐지(B03, B01·개인 기준선)의 설계를 다시 검토할 항목으로 남긴다.

## 통계 검정 결과: 탐지 설계의 두 가지 가정

- 작성일: 2026-10-05
- 계획: [00_검정계획.md](08_통계검정.md#source-1) (가설·방법·유의수준·표본은 실행 전에 고정했고 바꾸지 않았다)
- 코드: [scripts/12_stat_tests.py](../scripts/12_stat_tests.py)
- 출력: `data/12_stats/`

### 1. 요약

| 가정 | 검정 | 결과 (주 분석, Holm 보정) | 결론 |
|---|---|---|---|
| 가정 1: 정상 세션은 웹·서버 경로를 함께 쓴다 | 정확 이항검정, H0: p ≤ 0.90 | 142/142 = 1.000 (95% CI 0.979~1.000), p_holm = 6.4×10⁻⁷ | **지지됨.** 단, 일부는 세션 정의에서 오는 결과 (3절) |
| 가정 2: 사람마다 시작 시각이 달라 개인 기준선이 필요하다 | Kruskal-Wallis | H = 23.5, df = 7, ε² = 0.167, p_holm = 0.0014 | **차이는 있음. 하지만 "개인 기준선이 필요하다"까지는 약하게만 지지됨** (4절) |

- 주 분석 표본: 세션 146개 중 분석기획 문서(10/01)의 시나리오 세션 4개(S122, S132, S137, S142)를 뺀 142개
- 결과는 **탐색적**이다. 분석자가 데이터를 본 뒤 세운 가정이고, 합성 데이터일 가능성이 높다.

---

### 2. 검정 1: 정상 세션의 경로 동시 사용

| 표본 | server+web | 비율 | 95% 신뢰구간 | p (H0: p ≤ 0.90) |
|---|---|---|---|---|
| **주 분석 (시나리오 4개 제외)** | **142 / 142** | **1.000** | **0.979 ~ 1.000** | **3.2×10⁻⁷** |
| 민감도: 전체 | 143 / 146 | 0.980 | 0.948 ~ 1.000 | 1.8×10⁻⁴ |
| 민감도: 주 분석, 3단계 규칙 2 수정 전 | 142 / 146 | 0.973 | 0.938 ~ 1.000 | 7.5×10⁻⁴ |
| 민감도: 전체, 규칙 2 수정 전 | 143 / 150 | 0.953 | 0.914 ~ 1.000 | 0.014 |

**사람별 (주 분석):** admin01 23/23, analyst01 12/12, dev01 16/16, dev02 17/17, intern01 11/11, ops01 29/29, ops02 16/16, web01 18/18

- 네 표본 모두 신뢰구간 하한이 0.90을 넘는다. "거의 항상 함께 쓴다"는 가정이 표본 정의를 바꿔도 유지된다.
- 8명 모두 예외 없이 100%다. 특정 한두 명 때문에 나온 결과가 아니다.
- 시나리오 세션을 넣고(전체), 규칙 2 수정 전 기준으로 세어도(가장 보수적) 비율은 0.953이고 p = 0.014로 기준을 넘는다.

---

### 3. 검정 1의 해석에서 주의할 점

**이 결과 일부는 세션을 정의한 방식에서 나온다.**
- 3단계에서 세션은 ssh 접속을 기준으로 만들고, 같은 IP·시간의 웹 활동을 붙였다. 그래서 "server+web 비율"은 다음 두 가지를 함께 잰 것이다.
  - ssh 세션 중 웹 활동이 함께 있는 비율
  - 웹 활동 중 ssh 없이 따로 나온 비율
- 이 두 가지가 실제로 거의 항상 함께 나타났다는 건 데이터의 사실이다. 하지만 "server+web"이라는 묶음 자체는 우리가 정한 규칙의 결과다.
- 규칙 2를 고치기 전 기준(웹 활동을 더 엄격하게 자른 경우)으로도 0.953이라, 규칙 선택이 결론을 바꾸지는 않는다.

**의미:** B03(평소와 다른 접속 경로) 탐지의 전제가 데이터에서 뒷받침된다. 정상 세션 142개 중 경로가 하나뿐인 세션이 0개였으므로, 한쪽 경로만 나타나는 세션은 정상 기준선에서 매우 드문 사건이다.

---

### 4. 검정 2: 개인별 시작 시각 차이

#### 주 검정

| 표본 | n | H | df | ε² (효과 크기) | p |
|---|---|---|---|---|---|
| **주 분석** | **142** | **23.50** | **7** | **0.167 (중간~큼)** | **0.0014** |
| 민감도: 전체 | 146 | 21.66 | 7 | 0.149 | 0.0029 |

→ "8명의 시작 시각 분포가 모두 같다"는 H0를 기각한다. **사람마다 시작 시각 분포에 차이가 있다.**

#### 사람별 분포 (주 분석, KST)

| 사람 | n | 최소 | 1사분위 | 중앙값 | 3사분위 | 최대 | 사분위 범위 |
|---|---|---|---|---|---|---|---|
| ops01 | 29 | 08:25 | 10:26 | 12:41 | 15:09 | 17:19 | 283분 |
| ops02 | 16 | 08:26 | 10:45 | 13:05 | 14:42 | 16:22 | 237분 |
| dev01 | 16 | 09:32 | 10:18 | 11:47 | 15:28 | 17:14 | 310분 |
| admin01 | 23 | 09:06 | 10:15 | 12:45 | 15:47 | 17:23 | 332분 |
| intern01 | 11 | 10:26 | 10:40 | 13:46 | 15:27 | 15:46 | 287분 |
| web01 | 18 | 11:14 | 13:40 | 14:44 | 18:06 | 19:38 | 266분 |
| analyst01 | 12 | 10:09 | 14:06 | 16:07 | 16:22 | 16:44 | 136분 |
| dev02 | 17 | 10:16 | 14:01 | 16:07 | 16:48 | 18:09 | 167분 |

#### 사후 검정

- 두 사람씩 28쌍 Mann-Whitney 검정, Holm 보정 후 **유의한 쌍 0개**
- 전체로는 차이가 있지만, 사람당 세션이 11~29개라 어느 두 사람이 다른지까지 확정할 힘은 없다.
- 분포를 보면 중앙값이 늦은 쪽(analyst01·dev02 16시대, web01 14~18시)과 이른 쪽(dev01 11시대, ops01·admin01 12시대)으로 나뉘는 경향이 있다.

### 5. 검정 2의 해석: "차이가 있다" ≠ "개인 기준선이 꼭 필요하다"

| 관점 | 내용 |
|---|---|
| 통계적 유의성 | 있음 (p = 0.0014) |
| 효과 크기 | 중간~큼 (ε² = 0.167). 시작 시각 차이의 약 17%가 "누구인가"로 설명된다 |
| 실무적 겹침 | **크다.** 모든 사람의 사분위 범위가 대부분 10~17시 업무시간 안에서 겹친다 |
| 두 사람씩 비교 | 확정적인 쌍이 없다 |

**탐색적 관찰 (실행 후 추가, 8단계로 넘김):**

주 분석 표본 전체의 시작 시각 범위는 **08:25~19:38**이다. 이 전체 범위를 기준선으로 쓴다고 가정하면 다음과 같다.

| 세션 | 개인 기준선 B01 | 전체 범위 기준 |
|---|---|---|
| S122 (03시), S137 (02시) | 걸림 | **걸림** (범위 밖) |
| S026 (09시), S050 (17시), S053 (10시), S063 (10시) — 7단계 오탐 후보 | 걸림 | **안 걸림** (범위 안) |

- 이 데이터에서는 크게 벗어난 시각(새벽)이 전체 기준선으로도 잡힌다. 반면 개인 기준선의 작은 이탈(1~3시간)은 오탐의 원인이었다.
- 즉 **개인 기준선이 시간대 탐지에 주는 이득은 이 데이터에서 크지 않고, 오히려 오탐을 만들었다.**
- 단, 이 비교는 결과를 본 뒤 한 것이라 탐색적이다. 사람 수가 8명뿐이고 합성 데이터라는 한계도 있다.

**결론:** 가정 2는 **부분적으로만 지지된다.**
- 사람마다 시작 시각이 다르다는 건 맞다.
- 그러나 차이가 업무시간 안의 이동 수준이라, "개인 기준선이 꼭 필요하다"는 근거로는 약하다.
- 설계 검토 항목: B01을 "개인 범위 + 전체 범위 둘 다 벗어날 때"로 바꾸거나, 개인 범위 대신 분위수를 쓰는 방안을 성능평가 단계에서 비교한다. 이는 7단계 개선 목록 2번과 같은 방향이다.
