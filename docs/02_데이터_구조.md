- 작성일: 2026-09-29

- 목적: 프로젝트에서 사용할 데이터셋 4종을 정리하고, 각 데이터가 서버·호스트 원시 로그에 해당하는지 구분

### 1. 데이터셋 4종

| # | 테이블 | 로그 종류 | 형식 | 샘플에서 확인된 내용 |
|---|---|---|---|---|
| 1 | `security_logs.raw.sshd_raw` | **SSH 인증 로그** (OpenSSH) | syslog 텍스트 한 줄 | `bastion-01` 서버. 외부 IP `45.148.10.123`이 `oracle` 계정으로 접속 시도 (Invalid user) |
| 2 | `security_logs.raw.nginx_raw` | **웹 접근 로그** (Nginx) | combined 포맷 텍스트 | 내부 IP `10.20.10.11`이 `GET /api/logs` 요청 → 200 응답 |
| 3 | `security_logs.raw.sysmon_raw` | **호스트 이벤트 로그** (Linux Sysmon) | XML 한 줄 | `web-01` 서버에서 nginx 프로세스가 `10.10.1.20:443`으로 네트워크 연결 (EventID 3) |
| 4 | `security_logs.raw.teiren_audit_raw` | **테이렌 클라우드 감사 로그** | JSON (CEF 필드명 사용) | `dev01@lab.internal` 사용자의 IAM 로그인 성공 |

- 네 테이블 모두 원본 컬럼은 `RAW_LINE`(로그 원문)과 `LOADED_AT`(Snowflake 적재 시각) 두 개다. 분석하려면 먼저 파싱해야 한다.
- 로그가 나오는 위치로 나누면 다음과 같다.
  - **네트워크 경계:** sshd (서버 접속 시도)
  - **웹 서비스:** nginx (HTTP 요청)
  - **서버 내부:** sysmon (프로세스, 파일, 네트워크 활동)
  - **애플리케이션:** teiren_audit (사용자 행위)
- 이 구성이면 공격 흐름을 여러 로그에 걸쳐 따라가는 **교차 로그 상관분석**을 할 수 있다.

### 2. 서버·호스트 원시 로그에 해당하는가

대부분 해당한다. 다만 네 테이블의 성격이 모두 같지는 않다.

| 테이블 | 서버·호스트 로그인가 | 원시(raw) 로그인가 | 판단 |
|---|---|---|---|
| `sshd_raw` | ✅ 서버(`bastion-01`)의 OS 서비스가 남긴 로그 | ✅ syslog 원문 그대로 | **서버 원시 로그** |
| `nginx_raw` | ✅ 웹 서버가 남긴 로그 (추정 호스트 `web-01`) | ✅ combined 포맷 원문 그대로 | **서버 원시 로그** |
| `sysmon_raw` | ✅ 호스트(`web-01`)에 설치된 에이전트가 남긴 로그 | ✅ Sysmon XML 원문 그대로 | **호스트(엔드포인트) 원시 로그** |
| `teiren_audit_raw` | ❌ 서버·호스트가 아니라 **애플리케이션(테이렌 클라우드 콘솔)** 로그 | △ 이미 **CEF 필드명으로 정리된 JSON** | **애플리케이션 감사 로그 (반정규화 상태)** |

#### 정리

- **sshd·nginx·sysmon:** 서버나 호스트에서 나온 원시 로그다. 포맷이 제각각이고 파싱하기 전에는 필드 구분이 없어서, SIEM이 수집하는 전형적인 원시 로그에 해당한다.
- **teiren_audit:** 성격이 다르다.
  - 출처가 OS나 서버가 아니라 **SaaS 애플리케이션 안에서 사용자가 한 행위**다.
  - `tc_act`, `tc_suser`, `tc_src`처럼 **이미 SIEM이 정규화한 형태**라서 키로 바로 값을 꺼낼 수 있다. 테이블 이름에는 `_raw`가 붙어 있지만 실제로는 "파싱이 끝난 이벤트"에 가깝다.

#### 주의할 점

- 테이블 이름은 모두 `_raw`이지만, `LOADED_AT`은 Snowflake에 적재할 때 붙은 메타데이터라 원본 로그의 일부가 아니다.
- **실제 운영 서버에서 수집한 로그가 아니라 생성(시뮬레이션) 데이터일 가능성이 높다.** 네 테이블 모두 이벤트 시각(10-01)이 적재 시각(09-27)보다 늦다. 형식은 실제 원시 로그와 같지만, 발표나 보고서에서 "실제 운영 로그"라고 단정하지 말고 멘토에게 먼저 확인한다.

### 3. 발표용 표현

> **서버·호스트 원시 로그 3종(sshd, nginx, sysmon)과 애플리케이션 감사 로그 1종(teiren_audit)**

## 통합 데이터셋 컬럼 설명

> 4개 로그(NGINX·SSHD·Sysmon·감사로그)의 최종 정규화 파일을 시각순으로 위아래로 이어 붙인 타임라인이다. 로그끼리 조인하지 않았으므로 **한 행 = 원래 로그 한 줄**이다.

### 1. 파일 개요

| 항목 | 내용 |
| --- | --- |
| 파일 | `data/04_integrated/timeline.csv` (UTF-8 BOM) |
| 크기 | **9,125행 × 43컬럼** |
| 행 구성 | NGINX 2,223 + SSHD 1,364 + Sysmon 5,082 + 감사로그 456 |
| 기간 (UTC) | 2026-09-30 15:10:48 ~ 2026-10-16 14:11:45 |
| 정렬 | `event_time_utc` → `log_source` (nginx, sshd, sysmon, teiren_audit 순) → `source_row` |
| 입력 | `data/03_normalized/*_normalized_event_action.csv` 4개 |
| 생성 | `scripts/04_integrate.py` |
| 검증 | `scripts/99_verify_integrated.py` (25개 검사 통과) |

**컬럼 순서:** 공통 컬럼 13개 → 로그별 고유 컬럼 28개 (NGINX → SSHD → Sysmon → 감사로그) → `rawEvent`, `unmapped`

**빈칸의 의미:** 그 로그에 해당 정보가 없다는 뜻이다. "실패"나 "0"을 뜻하지 않는다. 예를 들어 NGINX 행의 `event_action`, Sysmon 행의 `http_method`는 항상 빈칸이다.

아래 표의 **값 있는 행**은 실제 통합 파일에서 빈칸이 아닌 행 수다.

**빈칸이 생기는 경우**

- **SSHD `src`:** 세션 줄 750행은 원문에 IP가 없어 빈칸이다.
- **SSHD `duser`:** `disconnect_received`, `session_logged_out`, `session_removed` 450행은 원문에 계정이 없어 빈칸이다.
- **Sysmon `suser`:** `process_terminate` 1,458행은 원문 값이 `-`라 빈칸으로 바꿨다. 원래 값 `-`는 `rawEvent`에 있다.

| 로그 | 키 |
| --- | --- |

`LOADED_AT`은 사건 시각이 아니라 데이터를 적재한 시각이다.

### 8. 읽을 때 주의할 점

| 주의점 | 내용 |
| --- | --- |
| 같은 초 안의 순서 | NGINX는 초 단위라 `.000000`으로 끝난다. 예: 디버그 실행은 NGINX `05:08:14.000`, 감사로그 `05:08:14.960`이지만 실제로 어느 쪽이 먼저인지는 알 수 없다 |
| 같은 사건의 중복 행 | 한 사건이 두 로그에 모두 남을 수 있다 (예: 디버그 실행은 NGINX와 감사로그에 각각 한 행). 건수를 셀 때는 `log_source`로 나눠 센다 |
| 같은 이름 ≠ 같은 계정 | Sysmon `suser`의 `dev01`(리눅스)과 감사로그 `suser`의 `dev01@lab.internal`(콘솔)은 다른 계정이다. `user_type`으로 구분한다 |
| IP의 역할 | `src`는 접속자 IP, `dvc`는 서버 자신의 IP, `dst`는 연결 목적지 IP다. 서로 다른 의미이므로 섞어서 묶지 않는다 |
| 로그인 건수 | SSHD는 `event_action = auth_success`만 센다 (`session_opened`까지 세면 중복). 감사로그는 `IAM_LOGIN_SUCCESS`, `ROOT_LOGIN_NO_MFA`, `IAM_LOGIN_NEW_DEVICE`만 세고, `SESSION_REFRESH`는 로그인이 아니다 |
| 민감 정보 | 감사로그 `unmapped.tenancy`(고객사 식별값)는 `rawEvent`에도 있다. 외부에 공유할 때는 두 컬럼 모두 마스킹한다 |
